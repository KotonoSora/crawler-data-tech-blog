# 04 — Step-by-Step Implementation Plan

Entry criteria: E0 scaffold green (baseline 06), V001/V002 migrations applied, roles granted.
Every task lands under `services/crawler-service/src/`, follows the definition of done (baseline
06 §4: tests with PG 18.6 + Redis 7.4 Testcontainers, metrics/logs, docs current), and is
verified by the acceptance goal in the table. Task IDs follow AGENTS.md; spec prefix is `02`.

| Task ID | Subsystem (BE/DevOps) | Step Description | Dependency | Acceptance Goal |
|---|---|---|---|---|
| BE-02-01 | BE | RobotsService: crawler-commons `Robotstxt` parser; load `/robots.txt` via the `FetchPort` interface (defined here, implemented in BE-02-05); 512 KB cap; cache `tb:robots:{host}` TTL 24 h (success) / 300 s (failed load); RFC 9309 semantics: 4xx -> allow all, 5xx/timeout -> disallow all; unit tests with a fake `FetchPort` | E0; file 01 §2 | AC-13: disallowed URL -> 0 HTTP requests, `fetch_log` row `robots_denied`; 4xx robots host -> fetch proceeds |
| BE-02-02 | BE | HostGate: global semaphore (4 hosts, `CRAWLER_GLOBAL_HOSTS`), per-host single permit, min-delay gate >=2000 ms (Medium-family >=3000 ms) driven by last-request timestamps; `tb:lock:host:{host}` NX for cross-role serialization; honors `tb:pause:{host}` (file 05 §2); tests with an injectable clock | E0 (Redis) | AC-15: test observes gaps >=2000 ms, never 2 in-flight requests for one host, <=4 hosts fetched in parallel |
| BE-02-03 | BE | ConditionalGetStore: read/write `http_cache` (V002); send `If-None-Match` / `If-Modified-Since`; 304 -> keep validators, refresh `checked_at`, outcome `not_modified`; guard re-GET for unarchived URLs | E0 (V002) | 304 responses consume 0 body bytes; re-crawl of an unchanged archived article counts `skipped`, 0 file rewrites (AC-02) |
| BE-02-04 | BE | RetryPolicy: attempts 1..5 with waits 30 s, 2 m, 10 m, 1 h, 6 h; `Retry-After` honored <=24 h, otherwise standard wait; `tb:retry` zset (member `articleId`, score ready epoch ms); due-scan moves members to `tb:q:{host}`; unit + Redis integration tests | E0 (Redis) | 5th failure -> `FETCH-BACKOFF-EXHAUSTED`, article `failed`; `Retry-After: 7200` sets a score 7200 s ahead; no attempt beyond 5 |
| BE-02-05 | BE | FetchClient (implements `FetchPort`): JDK `HttpClient`, HTTP/1.1, connect 10 s, read 30 s, total 60 s, redirects <=3 same-host, UA/Accept/Accept-Encoding headers, streaming caps (HTML 10 MB, robots 512 KB); tests against DO-02-01 | DO-02-01 | Slow endpoint -> `FETCH-TIMEOUT` within <=60 s; 11 MB body aborts at 10 MB with outcome `too_large`; cross-host redirect -> terminal |
| BE-02-06 | BE | OutcomeMapper + MediumTransientClassifier: HTTP status/exception -> one of the 9 outcomes + frozen failure code; Medium-family 000/403 -> `FETCH-MEDIUM-TRANSIENT`; 404 -> `failed`, 410 -> `skipped`, 429 -> `FETCH-RATE-LIMITED`; table-driven tests | BE-02-05 | Every outcome maps to exactly 1 code or none (BA 05); all 9 outcomes covered by tests; classification is deterministic |
| BE-02-07 | BE | FetchLogWriter: 1 `fetch_log` row per attempt + article fetch-state columns in 1 transaction (BR-17); purge maintenance pass (boot + job end) deletes rows older than 90 days, batches of 10,000 per host; purge counter | E0 (V001) | After N attempts exactly N rows exist; 0 UPDATE statements on fetch_log; 90-day boundary test passes; purge removes rows, not articles |
| BE-02-08 | BE | FetchTask orchestrator: consume `tb:q:{host}` -> robots -> HostGate -> conditional GET -> FetchClient -> OutcomeMapper -> FetchLogWriter -> `LREM` acknowledge; re-schedule paused hosts; hand `ok` bodies to extraction (spec 03) | BE-02-01..BE-02-07 | One article end-to-end: 1 row per attempt, correct outcome, message removed from `tb:q:{host}:processing` after commit; restart re-drives in-flight work |
| BE-02-09 | BE | Integration test suite (Testcontainers PG 18.6 + Redis 7.4) against the DO-02-01 fixture: happy path, 304, 429 with `Retry-After: 2 h`, disallowed robots.txt, >10 MB body, 5-attempt exhaustion | BE-02-08, DO-02-01 | All 6 scenarios pass; asserted `fetch_log` rows match expected outcome + attempt sequences; no processing entries left |
| DO-02-01 | DevOps | Loopback fixture server (test-only, no Docker dependency): serves robots.txt variants, ETag/Last-Modified resources, 429 with `Retry-After`, slow endpoint (35 s), 11 MB body; binds a random 127.0.0.1 port | — | Fixture starts in <=2 s; endpoints respond deterministically; reusable by BE-02-05 and BE-02-09 locally |
| DO-02-02 | DevOps | Metrics wiring: `crawler_fetch_total{outcome}`, `crawler_fetch_duration_seconds` histogram, `crawler_fetch_bytes_total`, `crawler_host_paused_total`; Actuator Prometheus endpoint; bounded labels (9 outcomes, <=20 hosts, no URL labels) | BE-02-06 | One fixture fetch moves all 4 metrics; scrape shows bounded label sets; no high-cardinality label |
| DO-02-03 | DevOps | Load smoke: 200 sequential fetches to 1 fixture host; assert 1 in-flight request, min gap >=2000 ms, elapsed 400-480 s, 0 failures; evidence recorded in docs | BE-02-09, DO-02-02 | Script exits 0; log excerpt + metric sample attached; a gap <2000 ms fails the run |

Ordering: BE-02-01..BE-02-07 develop in parallel after E0 (only BE-02-06 depends on BE-02-05);
BE-02-08 merges them; BE-02-09 gates the E1 exit criterion with DO-02-03. DO-02-01 is implemented
first so BE-02-05 is testable without network access.
